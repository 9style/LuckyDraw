# 分享海报（计划二 · 海报部分）设计

> 日期：2026-09-15
> 前置：`docs/superpowers/specs/2026-09-13-职场算命-design.md` 第十章（海报生成）、
> `docs/superpowers/plans/2026-09-13-职场算命-计划一-核心引擎与主链路.md`
> 范围：结果页新增「保存海报」，生成可长按保存的分享图。**不含口令解锁。**

## 1. 背景

设计文档第十章已完整设计了海报（尺寸、版式、五个技术坑、降级策略），但从未实现 ——
计划一明确把它划给计划二。本次落地的**只是海报这一半**，口令解锁不在范围内。

设计文档原本把海报设计成一个独立阶段（`intro|form|divining|result|poster`），
且入口在口令解锁之后。本次两个前提都变了，因此下述几处**刻意偏离原设计**，每处都给了理由。

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 口令解锁 | **不做** | 用户明确只要保存按钮。连带的 `lock` 文案、遮罩态、`unlocked` 流程全部不碰 |
| 二维码来源 | **静态图片**（`QRCode.png`） | 用户指定。零依赖、断网可用。代价见 §9 |
| 二维码内容 | `http://121.40.123.10:888/` | 用户确认为最终地址（已解码核对） |
| 海报形态 | **结果页上的全屏浮层**，非独立阶段 | 不新增阶段 → 不动 `STAGES`、不动 `restore()` 归一化、不动 `isUsableSession` |
| 渲染方式 | **纯 Canvas 2D 自绘** | 沿用设计文档 §10.1 的结论 |
| 海报内容 | 设计文档 §10.2 的 6 样 | 不加幸运彩蛋（底部空间不足，见 §5） |
| 按钮主次 | 保存海报 = 金色主按钮，再算一次 = 描边次按钮 | 分享是目标行为 |
| 坐标组织 | **元素流 + 声明间隙**，非绝对 y | 设计文档的绝对坐标违反它自己的底部边距约束，见 §5 |

### 被否决的方案（记录理由，避免重复讨论）

- **`html2canvas` 截取结果页 DOM** —— 设计文档 §10.1：雷达图本就必须用 Canvas 绘制，
  它反而要再截一次；省去 ~45KB gzip；且设计文档列出的 5 个已知坑（模糊/跨域空白/
  图片未加载完/滚动偏移/背景图）一个都不会遇到。
- **生成 SVG 再栅格化** —— `drawImage` 一个含中文文本的 SVG，在微信 XWeb 上有渲染成
  空白的风险；且中文字体测量问题并未真正消失（SVG 里的 `<text>` 仍要用系统字体度量）。

## 3. 架构与数据流

```
store.reading（冻结的，只读）
      │
      ▼
PosterModal.vue ──▶ renderPoster() ──▶ 离屏 canvas ──▶ toDataURL ──▶ <img> 展示
```

**海报不重新计算任何东西。** 用的就是 `DivinationView` 在动画结束那一刻算定并冻结的
`reading`。海报上的分数、签文、身份标签必然与用户屏幕上看到的一致 —— 这守住了项目最
核心的「结果冻结」约定。

**阶段机不变**：仍是 `intro | form | divining | result`。浮层由 `ResultView` 内部的布尔量
控制，**不进 `store`、不进 `STAGES`、不落 `sessionStorage`**。刷新后浮层自然关闭、回到
结果页，正是想要的语义。

## 4. 模块划分与可测边界

| 文件 | 职责 | 可测性 |
|---|---|---|
| `src/config/poster.json` | 元素流、间隙、字号、配色 | 纯数据 |
| `src/core/poster/measure.js` | `fitFontSize` / `wrapText` | **纯函数，node 下真测** |
| `src/core/poster/layout.js` | 由 `poster.json` 求出各元素 y | **纯函数，node 下真测** |
| `src/core/poster/draw.js` | `roundRect`（自写）、星点阵、雷达图 | 几何可测，绘制不可测 |
| `src/core/poster/poster.js` | 编排并产出 canvas | 薄 |
| `src/core/poster/clipboard.js` | 三段式复制 | **纯逻辑（依赖注入），可测** |
| `src/components/PosterModal.vue` | 浮层 UI、生命周期 | 人工 |
| `src/views/DebugPoster.vue` | dev-only 验收页 | 人工 |

**`measure` 由外部注入**：浏览器传 `ctx.measureText` 的包装；测试传假测量器
（约定：中文/全角 1em、ASCII 0.5em、其余 1em）。这是把「会悄悄坏的部分」变成
「跑 `npm test` 就知道的部分」的关键。

`clipboard.js` 同样注入依赖（`navigator.clipboard`、`document.execCommand` 的包装），
让三个降级分支都能在 node 下测到。

## 5. 版式与不变式

### `poster.json` 形状

不写死绝对 y，而是元素流 + 声明的间隙，由 `layout.js` 顺序求值：

```json
{
  "canvas": { "w": 750, "h": 1334, "marginTop": 64, "marginBottom": 16 },
  "palette": { "gold": "#e8c074", "textMain": "#f2ecff", "textSub": "#b8a9d9" },
  "elements": [
    { "key": "title",    "h": 42, "gap": 22, "font": 34, "maxWidth": 620, "color": "gold" },
    { "key": "subtitle", "h": 24, "gap": 68, "font": 18, "maxWidth": 620, "color": "textSub" },
    { "key": "name",     "h": 70, "gap": 18, "font": 64, "maxWidth": 620, "color": "textMain" }
  ]
}
```

（上面只列前三个元素作为形状示例，`palette` 与 `font`/`gap` 的取值在实现时按
`?debug=poster` 的人眼结果微调；`canvas` 尺寸与 `marginBottom` 由测试钉死，不可改。）

元素顺序：`title / subtitle / name / identity / radar / scoreRow / fortune / qrcode / scanHint / disclaimer`。

### 为什么改掉设计文档的绝对坐标

设计文档 §10.2 的坐标表排到 **y=1328，底部只剩 6px**，而它在同一节写着约束
「底部保留 ≥16px 安全边距」—— 自相矛盾。改成元素流后，各元素 y 由
`marginTop` 与逐个 `gap` 累加得出，**间距取值本身来自 `poster.json`，不是自动压缩的**；
元素流的价值是把「排到哪了」变成可计算、可断言的量，从而让下面这条约束能被测试卡住。

初始取值（已核算满足约束，底部余量 26px）：

```
y=64   title(42)  ─22→  y=128  subtitle(24) ─68→  y=220  name(70)
       ─18→  y=308  identity(70) ─30→  y=408  radar(300) ─30→  y=738  scoreRow(30)
       ─30→  y=798  fortune(230)  ─34→  y=1062 qrcode(140) ─22→  y=1224 scanHint(24)
       ─12→  y=1260 disclaimer(48) → 1308；1334 − 1308 = 26 ≥ 16  ✓
```

**该约束落为单元测试**（不是散文）：

```
断言：最后元素的 y + h ≤ canvas.h − canvas.marginBottom
```

同样进测试的还有：元素互不重叠、`canvas.w/h` 为 750×1334、必需元素 key 齐备。

### 不加幸运彩蛋

四件套（幸运色/数字/方位/星座）约需 120px。设计文档版式已占用 1328px，加入必须压缩
雷达图（300→~190），而雷达图是海报的视觉主体。保持设计文档的 6 样。

## 6. 文字自适应

**偏离设计文档 §10.3.1**：它规定姓名按字数分档（1-3 字 64px / 4-5 字 52px / 6-8 字 42px）。
该规则对非中文名失效 —— 「Alexander」9 字符会落到最小档，而它在 52px 下就放得下。

改用**测量驱动的降档搜索**：

```
fitFontSize(text, maxWidth, { max, min, step }, measure)
  从 max 起按 step 递减，取第一个 measure(text) ≤ maxWidth 的字号
  降到 min 仍放不下 → 返回 min，交由 wrapText 折行
```

设计文档的分档数值保留为各元素的 `max`（姓名 64 等），不再按字数硬切。

`wrapText` 规则：

- 中文（含全角标点）**按字累加宽度**换行，不按空格断词
- ASCII 单词**按空格断词**，超宽的单词硬切
- 中英混排逐字符判断，标点不置于行首（悬挂处理）

`measure` 与字号均为 `poster.json` 决定，最终像素值在 `?debug=poster` 页人眼微调。

## 7. 二维码

`QRCode.png` 的静默区只有约 **2 个模块**（规范建议 4）。将二维码**画得比白卡小**，
用卡片留白补足：

```
白底圆角卡 140×140
  └─ 二维码 116×116 居中 → 卡片左右各留 12px
     图内自带白边折算：116 × (25/400) ≈ 7.25px
     合计静默区 ≈ 19.25px
     符号占 116 × (350/400) ≈ 101.5px；29 模块 → 模块 ≈ 3.5px
     19.25 ÷ 3.5 ≈ 5.5 个模块  ✓（规范要求 4）
```

（白边 25/400、符号 350/400、29 模块、版本 3 均为实测值。）

**两件必须做的事**：

1. **绘制前 `await img.decode()`** —— 否则 `drawImage` 画出一块空白。这正是设计文档
   §10.1 列给 html2canvas 的「图片未加载完」坑，用 Canvas 也得自己躲。
2. **图片移入 `src/assets/qrcode.png` 并用 `import` 引用，且纳入版本控制。** 它当前在
   仓库根目录且未被 git 跟踪。`base: './'` 下由 Vite 重写 URL 才能保证子目录部署正确；
   不提交则他人拉取后构建直接失败。

### 星点阵

按设计文档 §10.3.2，用固定种子 `makeRng(20260913)` 生成星点坐标。进出浮层时星点位置
完全一致，避免「图片在闪」的观感。

## 8. 交互与浮层

### 入口

`ResultView.vue` 底部，与「再算一次」并排。文案进 `copy/ui.json`：

```json
"savePoster": "保 存 海 报",
"posterHint": "长按图片保存到相册",
"posterDownload": "下载图片",
"posterPending": "正在为你绘制海报…",
"posterFailed": "海报生成失败，结果页仍可正常查看",
"copyLink": "复制链接"
```

`copy/ui.json` 会被合规闸门扫描，这些文案同样受禁用词与 60 字限制约束。

按钮样式：保存海报用既有 `.btn-gold`；再算一次改为描边次按钮（`theme.css` 新增
`.btn-ghost`，当前没有次级按钮样式）。

### 浮层行为

```
点「保存海报」→ 浮层打开，先显示 posterPending
             → 离屏 canvas 绘制 → toDataURL → <img> 替换
关闭：点遮罩空白 / 右上角关闭按钮 / Esc
```

- 打开时**锁背景滚动** —— 结果页很长，不锁会滚穿
- `prefers-reduced-motion: reduce` 时关闭淡入动画（沿用 `animation.css` 既有惯例）
- 微信内显示「长按图片保存到相册」；非微信显示「下载图片」按钮（UA 判断 `/MicroMessenger/i`）

### 导出格式

PNG 优先；`dataURL.length > 1.2MB` 时自动重画为 **JPEG 0.92**（设计文档 §10.3.5）。
海报是不透明深色背景，转 JPEG 不丢透明通道。

## 9. 降级与错误处理

### 海报渲染失败

`renderPoster` 抛异常时，浮层内显示 `posterFailed` + 「复制链接」。

**兜底态是一个完整可读的结果页**（设计文档 §10.5 硬要求）—— 这一条由浮层形态自动满足：
结果页从未被替换掉，一直在浮层底下，关掉浮层即可继续使用。

### 复制链接：HTTP 部署下的真问题

`navigator.clipboard` 要求 secure context，而部署地址是 **`http://121.40.123.10:888/`**
（纯 HTTP），**该 API 在此页面上不存在**。因此必须三段式：

```
navigator.clipboard.writeText()
  └─ 失败/不存在 → document.execCommand('copy')（临时 textarea，非 HTTPS 下仍可用）
      └─ 再失败 → 显示可选中的地址文本，提示手动复制
```

三个分支均有测试覆盖。只写第一段会让降级路径本身崩溃，而那正是它最该起作用的时刻。

## 11. 开发期验收页

设计文档 §596 要求并排渲染极端输入供人眼扫查。仓库无路由，故不走路径约定，改用查询参数
**`?debug=poster`**。

⚠️ 初稿写的「整体被 `import.meta.env.DEV` 包住，生产构建摇除」**按字面实现是不成立的**：
最直白的写法（文件顶部静态 import + 模板 `v-if="debugPoster"`）**摇不掉** —— `<script setup>`
会把模板里引用的绑定包一层 `unref()`，条件于是编译成 `unref(false)`，而 `unref` 是运行时函数调用，
压缩器折不掉，组件的引用就一直挂着，整个 DebugPoster 都会进产物（实测确认）。
真正生效的写法是 `App.vue` 里的**模块级条件三元 + `defineAsyncComponent`**：`import.meta.env.DEV`
在生产构建被替换成常量 `false` 后三元整条被折掉，动态 import 根本不进依赖图。
**改动这段接线前先在产物里搜 `DebugPoster` 的用例字符串** —— 这个坑不会以任何其它方式报出来。

渲染 13 条：第 0 条是 **1:1 原尺寸**的常规输入（基线），其余 12 条是极端输入
（1 字姓名 / 8 字全角姓名 / 最长身份标签 / 最低分 / 最高分 / 最长签辞等）。

第 0 条为什么必须按原尺寸铺开：栅格里的缩略图最小只有 220px 宽，16px 的免责声明、
二维码静默区、烫金边框的余量，在那个尺寸下全都判断不了；而 `index.html` 的
`user-scalable=no` 让「把浏览器放大」这条退路在手机上根本不成立。所以本页至少要有一张
能按真实像素看的 —— 否则「本功能唯一的视觉验收手段」这句话是空的。

**这是本功能唯一的视觉验收手段。** 中文没有内嵌字体、不同机型字宽不同，单测只能保证
「按假测量器不溢出」，真机仍必须走一次：iOS Safari / 微信 XWeb / Android Chrome 各一次，
覆盖海报长按保存与转发（设计文档 §607 已列此项）。

## 12. 已知风险与已接受项

| 风险 | 状态 |
|---|---|
| 二维码内容是 `http://121.40.123.10:888/`：**IP 非域名**，ECS 换 IP/重建后已分享的海报全部失效且无法追回 | **用户已确认接受** |
| **非标准端口 888**：部分企业网络/公共 WiFi/运营商可能拦截非 80/443 出站 | 已接受（现场多用蜂窝网络） |
| **HTTP 非 HTTPS**：微信可能提示「非官方网页」；`navigator.clipboard` 不可用 | 已接受，降级见 §9 |
| 二维码图片内容焊死，换地址需重新生成图片并重新构建 | 已接受 |
| 二维码静默区靠白卡留白补足（≈5.5 模块） | 已通过几何计算验证，见 §7 |
| 中文字体只能用系统字体，不同机型版式有差异 | 设计文档 §10.3.1 既定代价，靠自适应 + debug 页缓解 |
| 产物无 Service Worker，断网刷新不可用 | 计划一既定决策，本次不变 |
